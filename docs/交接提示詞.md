# 交接提示詞

在新的 Claude 帳號開一個新對話，**把整包 zip 上傳上去**，然後複製下面整段當作第一則訊息。

---

## 複製這一段 ⬇

```
我在做一款要上架 Google Play 和 App Store 的手機遊戲「GOO BLASTER」，
之前跟另一個 Claude 帳號合作到一個段落，現在要把工作搬過來繼續。

我已經把完整的交接包上傳給你了。請先照這個順序讀：

1. docs/02-開發日誌與決策紀錄.md ← 最重要，包含所有已否決的方案、
   已抓到的 bug 與成因、測試方法論、以及過程中犯過的錯誤
2. docs/03-已知問題與待辦.md ← 目前卡住的問題和下一步
3. docs/01-策略與修訂規格.md ← 市場定位、定價依據、上架時程
4. game/index.html ← 遊戲本體，單一檔案約 2000 行

幾件我希望你延續的工作方式：

- 用繁體中文回覆
- 改完程式碼要用 Playwright 實際跑過驗證，不要只看程式碼就說「應該可以」。
  tests/ 裡有現成的測試腳本可以直接用或改

  每次動難度都要重跑確認
- 如果某件事你只是推測、沒有驗證，請明講那是推測。
  之前有好幾次是因為誠實說「我猜錯了」才找到真正的原因
- 不要因為我是新手就迴避技術上的壞消息

讀完之後，先告訴我你對目前狀態的理解、以及你認為下一步該做什麼，
我們對齊之後再開始動手。
```

## 上傳時的注意事項

1. **把 zip 解開後整包上傳**，不要只上傳 `index.html`。
   `docs/` 裡的三份文件是新 AI 能不能接上手的關鍵。
2. 如果新帳號的上傳有檔案數量限制，**最低限度要傳這四個**：
   - `docs/02-開發日誌與決策紀錄.md`
   - `docs/03-已知問題與待辦.md`
   - `docs/01-策略與修訂規格.md`
   - `game/index.html`
3. 新帳號如果也有「專案（Project）」功能，建議建一個專案並把 `docs/` 放進去，
   這樣之後每個新對話都自動看得到，不用每次重傳。

---

## 有些東西不會跟著轉移

| 項目 | 說明 |
|---|---|
| 對話紀錄 | 不會轉移。`docs/02` 就是為了取代它而寫的 |
| 專案（Project）裡的文件 | 綁在原帳號，要手動重新上傳 |
| 雲端工作環境裡的檔案 | 是暫時的，這個 zip 就是完整快照 |
| 手機上的遊戲進度 | 存在手機瀏覽器的 localStorage，跟帳號無關，不受影響 |

---

## 搬過去之後，建議的第一件事

**先解決「手機上無法移動」**（`docs/03` 第一項），因為它擋住所有真機測試。

最快的驗證路徑：用 `tools/啟動測試伺服器.bat` 在桌機起一個本機伺服器，
手機連同一個 Wi-Fi 用 `http://192.168.x.x:8000` 開 —— 而不是直接開下載的 HTML 檔。

如果這樣就能動，那問題從來不在程式碼裡，而在開啟方式。
