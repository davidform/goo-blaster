# 已知問題與待辦

版本：v0.9.3

## 🔴 最優先：手機上無法移動角色（未解決）

### 症狀

使用者把 `index.html` 下載到手機打開，**畫面正常、按鈕能按、可以進入遊戲，
但手指滑動時角色不會移動**。桌機瀏覽器與 Playwright 模擬環境下都正常。

### 已經排除／已經修過的

| 假設 | 處理 | 結果 |
|---|---|---|
| `TouchList` 在 iOS Safari 不可迭代，`for...of` 丟 TypeError | 全部改成索引迴圈 | 仍未解決（而且**無法用合成 TouchEvent 證實這個假設**） |
| `SFX.unlock()` 在舊 WebView 丟錯，例外冒穿 touchstart handler 導致搖桿沒啟動 | 音訊初始化整段包 try/catch、`SFX.unlock()` 移到搖桿啟動之後 | 仍未解決 |
| `touchSeen` 被提前設成 true，把 Pointer Events 後援永久鎖死 | 改成只有處理成功才設定，且改為「2 秒內沒 touch 就讓 Pointer 接手」 | 仍未解決 |
| 靠 `Touch.identifier` 比對搖桿，漏掉一個 touchend 就永久卡死 | **改成完全無狀態**：每次事件都從 `e.touches` 重新挑一根不在按鈕上的手指 | 仍未解決 |

### 最可能的剩餘原因（尚未驗證）

**使用者是用 `file://` 開啟本機 HTML 檔。** 行動瀏覽器對 `file://` 有諸多限制，
而且從聊天軟體或檔案管理員點開時，經常是被某個 App 的**內建預覽器**接手，
觸控事件會被它自己的手勢先攔走。

**驗證方式（下一步該做的）**：改用 `http://` 或 `https://` 網址開啟。
工具已經備好：
- `tools/啟動測試伺服器.bat` → 手機連同一 Wi-Fi 開 `http://192.168.x.x:8000`
- 或部署到 GitHub Pages 用 `https://` 開

**如果換成網址就能移動 → 程式碼沒問題，把診斷列拿掉即可。**
**如果還是不能動 → 需要看診斷列的數字才能繼續。**

### 遊戲內已內建的診斷工具

**主畫面最下方**：
```
v0.9.3　·　觸控 0 · 指標 0 · 滑鼠 0 · 音訊 無聲:未啟動
⚠ 目前是 file:// 開啟，建議改用網址開啟
```

**遊戲畫面左下角**（即時）：
```
觸控 12/340/11   指標 0/0   搖桿 ON 0.87   座標 245,-98
```
依序是 touchstart/touchmove/touchend 次數、pointer 事件次數、搖桿狀態與推桿量、角色世界座標。
超過 2.5 秒完全沒收到輸入時，畫面中央會顯示紅字「⚠ 偵測不到任何觸控事件」。

### 依診斷結果的分流

| 診斷顯示 | 意義 | 該做什麼 |
|---|---|---|
| 觸控三個數字都是 0 | 事件根本沒進到頁面 | 問題在開啟方式，不在程式碼。改用網址開 |
| 數字在跳但搖桿 off | 事件有進來但被判定成按在按鈕上 | 調整 `inBtn`/`inMute`/`inShk` 的判定範圍 |
| 搖桿 ON、座標在變，但角色沒動 | 輸入正常，是渲染問題 | 檢查相機與繪圖 |
| 指標有數字、觸控是 0 | 該瀏覽器只送 Pointer Events | 加強 Pointer 分支 |

> **確認能動之後，記得把診斷列整段刪掉**（在 `drawHUD()` 裡，
> 有註解標示「觸控診斷（真機除錯用 —— 確認能動之後就可以整段刪掉）」）。

## 🟢 可以考慮的調整（都不是 bug）

- **第 1、2 關可能太簡單**：笨 bot 零失誤通關。如果真人也覺得無聊，
  可以把第 1 關縮短、或讓第 2 關的落差再大一點
- **「活力粉紅」卡讓愛心可以疊到 7**：bot 每次都優先選它。
  如果希望「三顆心」成為遊戲識別特徵，可以降低上限或改成一次性護盾
- **難度旋鈕的位置**：`LEVELS` 陣列裡每關的 `rate`（出怪率）、`hp`（血量倍率）、
  `bossHp`、`espd`（敵人移速）、`bspd`（彈速）、`atkSlow`（攻擊間隔）
- **音樂旋律**：`PROG`（和弦進行）與 `ARP`（琶音音型）兩個純資料陣列，改了立刻聽得到
